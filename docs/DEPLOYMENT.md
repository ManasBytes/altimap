# Hosted scene studio

The public viewer is [altimap-demo.vercel.app](https://altimap-demo.vercel.app).
Vercel serves the frontend; the prepared scene collection lives in the public
[Dilavesh/altimap-demo dataset](https://huggingface.co/datasets/Dilavesh/altimap-demo).
Only the frontend and saved-scene collection are currently deployed. The public site does not
process new TIFF, GeoTIFF, PNG or JPG uploads. It replays previously generated predictions.
Use the local app and Python inference server to process your own files. Hosted live inference
would require a separate reachable backend; that is not available in the current public demo.

## Scene collection and layout

The viewer opens Chungthang automatically. **Scenes → Demos** offers image cards for
Chungthang town, Namchi, Chungthang forest, Pittsburgh bridges and three reference-scored
examples. **Reference** contains the separate bundled
GAMUS LiDAR previews; those are labelled reference heights, not model predictions.

The 3D viewport sits beside a docked inspector with Scenes, View, Measure, Accuracy and
Context tabs. Mobile screens stack the scene and inspector. The light survey-paper theme
and dark theme both use locally served fonts. Textures finish loading before a saved scene
is shown. Data, source dates and accuracy limitations remain visible in scene details.

Prepared results retain their RGB textures, display geometry, elevation grids, reference
metrics and raster exports. Display changes do not rewrite predictions or validation.
The Sikkim and Pittsburgh bridges scenes have no attached independent height reference.
Public DEM agreement measures coarse elevation consistency, not building-height accuracy.
OpenStreetMap markers and lists are cached map context, with estimated elevations.
Main's Python upload backend does not yet fetch this context for new images. The saved demos
may contain results generated by newer experimental backend code. Showing them does not adopt
that code or prove live context inference. See the [local check](local-studio-verification-20261005.md).
Attribution and model/data terms are retained in the HF dataset card.

## Frontend configuration

Use `frontend` as the Vercel root directory; `frontend/vercel.json` selects Vite and `dist`.

| Variable | Value |
|---|---|
| `VITE_DEMO_CATALOG` | `https://huggingface.co/datasets/Dilavesh/altimap-demo/resolve/main/index.json` (also the default) |
| `VITE_API_BASE` | `disabled` for prepared scenes only; the VM's HTTPS origin when live uploads are ready |

A blank API base uses the local same-origin server/Vite proxy. Public build variables contain
no credentials. Saved assets and downloads resolve against their result URL; live downloads
resolve against the API origin. Health checks disable uploads while processing is unavailable.
Copernicus/SRTM selection and optional public-DEM comparison retain the current main API contract.

After configuring the public variables, deploy from the intended source checkout:

```bash
cd frontend
npm ci
npx vercel deploy --prod
```

The current project uses CLI deployments. GitHub automatic deployment is not connected to
the Vercel account. Publishing a Git commit does not itself update production.

## Local preview

```bash
cd frontend
npm ci
VITE_API_BASE=disabled npm run build
npm run preview
```

To process new files locally, use a blank API base, rebuild, and start `viewer.server` as
described in [SETUP.md](../SETUP.md). New API inference is independent of the prepared demos.
